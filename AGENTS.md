# AGENTS.md - guidance for coding agents in vn-harness

This file is the quick-start brief. Read `ARCHITECTURE.md` for the deep dive.

## What this repo is

Personal plugin pack for DeepSeek Harness. It installs into ONE place only:

- the web profile: `npx @deepseek-ai/dsh web` (profile `web` under `DSH_HOME`,
  default `~/.dsh`)

DSH Desktop support was removed on purpose - the desktop app runs its own frozen
generation snapshot and this pack targets the raw web install alone. Do not add
desktop detection, a `-Target desktop` switch, or desktop install steps back.

What DOES exist is the `run-desktop.bat` + `app/` pair (see Layout): a small
Rust/Tauri shell that starts the very same pinned `dsh web` on a FREE loopback
port and shows THAT url in a native window instead of Chrome. It is a LAUNCHER,
not a desktop edition: it installs nothing, detects no host, disables no row,
touches no core or profile file, and loads the same live-linked bundles a
`run.bat` tab loads. Keep that distinction when editing - the rule above forbids
the desktop EDITION, not a second way to open the web profile - and do not delete
`app/` as leftover "removed desktop support".

Everything is a standard dsh **bundle**: an npm package with
`dsh.bundle` (+ `cordis.patch.yml`) and, for UI plugins, `dsh.client` and an
`exports["./client"]` browser bundle. Nothing patches DeepSeek core files.

**Platforms.** The plugins are plain JavaScript and must stay OS-neutral; the
only per-OS code allowed is a launcher choosing the right command for the host
(see `packages/dsh-open-in-app`). The tooling is split by host, not shared:
**Windows** runs PowerShell (`scripts/*.ps1`, on Windows PowerShell 5.1 *and* 7 -
use `Join-Path`, `[System.IO.Path]::PathSeparator` / `DirectorySeparatorChar`,
`$PSVersionTable` (never `$IsWindows` unguarded - 5.1 has no such variable) and
the `Get-ToolPath` / `Get-ToolNames` helpers instead of hardcoding `npx.cmd`,
`npm.cmd`, `powershell.exe`, `%USERPROFILE%` or `\` separators); **macOS/Linux**
run POSIX shell (`scripts/*.sh`) and must NEVER require PowerShell - they need
Node.js with npm/npx and nothing else. Both halves do the same work with the same
flags, and entry points come in pairs: `install.bat` / `install.sh`,
`uninstall.bat` / `uninstall.sh`, plus the console twins `scripts/*.bat` /
`scripts/*.sh`. The run launcher is a pair per host: `run.bat` + `run.sh` at the
repo root are the two ENTRY POINTS (one double-click each, and `run.bat` is batch
so no execution policy is involved), and only the Windows half is split further -
`run.bat` forwards its flags to `scripts/run-web.ps1`, which sits beside the
installer scripts and holds the work. That split is FORCED, not stylistic: cmd's
`for /f` reads a child's output only up to EOF, so a pure batch launcher cannot
see the ready line while the harness is still running, and the watching half needs
PowerShell. macOS/Linux need no worker, because POSIX `read` streams a FIFO line by
line.
`scripts/sync-vendored.ps1` is the one exception:
maintainer tooling for moving the forks forward, and it wants `pwsh` on
macOS/Linux.

**The run launcher.** `run.bat` / `run.sh` start the pinned
`npx @deepseek-ai/dsh@<pin> web --no-open`, stream the app's own output to the
terminal, read the ready line it prints once the server is listening
(`dsh web: http://127.0.0.1:<port>/?token=<launch token>`) and open THAT url in
Chrome, falling back to the default browser. Two rules are load-bearing and must
survive any edit: the launch token is a live credential, so it is read IN MEMORY
and never written to a file, echoed by us, or handed to a shell (it reaches the
browser as one argv element), and a URL that does not name a loopback address is
refused instead of opened. Both halves hold that first rule: the POSIX half reads
a FIFO from the main shell without ever putting a path in the middle, and the
Windows half is `run.bat` -> `scripts/run-web.ps1`, which reads the URL from the
app's output in PowerShell and hands it over with
`Start-Process -ArgumentList @($Url)` - one argv element, never a command string.
The two halves mirror each other flag for flag
(`-Port`, `-DshHome`, `-DshVersion`, `-NoBrowser`, `-DefaultBrowser`), and each
reads `.dsh-version.json` from the REPO ROOT: `run.sh` finds it with `$script_dir`
(it lives at the root) while `scripts/run-web.ps1` uses
`Split-Path -Parent $PSScriptRoot` - so moving that worker means fixing that line,
and `run.bat` itself has to stay at the root beside `run.sh`.

## Layout

Its name is the only one here that sorts last and `dsh plugin add` appends, so it is the profile's **final layer**: the slot that can restate any pack or core row. Pack-wide patches belong here, not in the bar

The disables stay with the row they replace (the bar), never the master, so `-Plugin dsh-rightbar` still mounts exactly one bar.
  - `packages/dsh-rightbar-files/lib/client.js` - GENERATED fork of `@deepseek-ai/dsh-client-ui-sidebar-files`: the Files tab type on top of the bar

"+" -> Editor opens a BLANK document; Save names it (extension included) through the shared `modals` dialog and creates it in the session workspace folder. **Markdown is claimed too** (it is text): a `md`/`markdown` tab shows a toolbar **Preview** button that reads the shipped document preview's kind from the tab registry and hands the address to it as `ctx.get('sidebarRight').openResource(address, { kind, replaceTab })`. Its CodeMirror palette follows the app's light/dark theme (oneDark only while the app is dark, a CodeMirror `Compartment` reconfigured live off `ctx.get('theme')` / `theme/change`, `body[data-ds-dark-theme]` as the fallback). Every one of the five is wrapped by ONE guarded call site (`streamLanguage(CM, name)`), which opens the document unhighlighted plus one console warning when the loaded engine does not carry the mode - the alpha.12 fix for the alpha.11 bug where a client bundle newer than its engine asked for `rust` and `StreamLanguage.define(undefined)` killed the tab with "Cannot read properties of undefined (reading 'languageData')". The engine and the bundle are kept in step from both sides: the request is version-qualified (`?v=<bundle version>`) and the route answers `cache-control: no-cache` over a content-hash ETag and re-`stat`s the artifact per request, so a rebuilt engine needs no restart. The rendered page also **undoes what the preview's plain-text scrollport imposes** on its contents (`white-space:pre` and the mono font stack), so a Markdown document draws as a document and its **Edit** pill wears the app font (alpha.8)

  - `packages/dsh-editor/lib/vendor/cm6.min.js` - GENERATED vendored CodeMirror 6 (rebuilt from `vendor/` - `entry.js` plus the hand-written `batch-mode.js` - never hand-edited)

No fork, no disabled core row, nothing for `sync-vendored.ps1` to track
  - `packages/dsh-image/` - **images as a surface** (row `image`, tab kind `image`): PNG, JPEG, GIF, WebP, AVIF, BMP, ICO, SVG and TIFF open in a viewer that FITS the pane on open, zooms on a ladder (5%-800%) with fit-to-pane and 100%-actual-pixels, wheel-zooms at the pointer with Ctrl/Cmd (a trackpad pinch is the same gesture, and the listener is attached NATIVELY with `{passive:false}` because React's own wheel listener is passive and a `preventDefault()` inside it does nothing - the browser's own Ctrl+wheel page zoom would then fire on top), drags to pan with a grab cursor MEASURED from real overflow, and double-clicks between fit and 1:1. The load-bearing rule is the pack's own: the zoom moves the LAYOUT (a box sized `naturalPixels * zoom` inside a scrollable pane), never a CSS transform, so panning is the pane's `scrollLeft`/`scrollTop` and a zoomed picture stays scrollable to its edge; a zoom keeps the point the reader was looking at, remembered as a fraction before the layout changes and restored on the next animation frame; fit shrinks but never enlarges; `margin:auto` on the box is the centring that survives overflow. A checkerboard behind the box shows a transparent PNG as transparent, past 300% the picture is drawn pixelated, and the status line names the true dimensions, the size on disk, the format and the SOURCE PIXEL under the pointer with its colour - sampled by drawing a 1x1 source rectangle into a 1x1 canvas, so inspecting an 8000px photograph never copies the picture into a second buffer. It is **client-only on purpose**: bytes come from the harness's own `remote.workspaceFiles.readAll` (the same call the shipped preview makes for a bytes-complete document, which already resolves the path inside the conversation workspace, refuses a symlink out, requires a regular file and enforces the 32 MiB single-file cap on the HOST side), so the package ships NO route, NO host state and NO path policy of its own - `lib/index.js` is one no-op row whose only job is to put the browser bundle in the boot graph, and the base64 payload is decoded with one indexed loop rather than `Uint8Array.from(atob(x), fn)` (a mapper call per byte is the difference between an instant open and a visible stall at the cap). The tab type is `extension`-band with the image suffixes and a `canOpen` that refuses anything else, so it REPLACES the shipped preview's bare intrinsic-size image **by RANKING** (extension 3 beats the shipped `text` type's fallback 1) and never by disabling a core row: every other file type keeps the surface it had, the preview stays mounted as the fallback, and the editor (which vetoes images outright) is untouched. There is deliberately NO guide entry - a blank image is not a document the "+" control should offer. TIFF is claimed on purpose: a browser that cannot decode it gets one clear sentence naming the format instead of a generic binary-file message. No fork, no core row disabled, nothing for `sync-vendored.ps1` to track
  - `packages/dsh-audio/` - **audio as a surface** (row `audio`, tab kind `audio`): WAV/RIFF (RF64 included), AIFF/AIFC and FLAC open as a WAVEFORM - one TRACK per channel, each in a ROW of its own (a file with eight channels shows eight rows, never eight overlays) drawn full width, with the 48px gutter beside each row a cell of EXACTLY that row's height holding the track's name and its amplitude reading together (L/R for a stereo pair, numbers past that, and NO letter at all for mono - a lone "M" is a letter the reader has to decode, and one track has nothing to tell apart from). **The track height belongs to the reader**: the hairline at the bottom of any row is a resize handle (the cursor becomes `ns-resize`) and dragging it changes EVERY track at once, 24px to 420px, because a waveform is read across tracks and separately sized tracks would no longer line up - ONE shared height in `trackHeight`, with the envelope, the ruler and the gutter cells all following it. An adaptive time ruler whose label widths are MEASURED so they never collide, the min/max envelope FILLED with the RMS drawn inside it as a lighter band, a linear or **dBFS** amplitude scale (72 dB) and an amplitude gain on Shift+wheel with NO button (the toolbar counts tracks instead), zoom by `pxPerSecond` from 1 (an hour in a pane) to 500000, with samples drawn as STEMS past ~3 px per sample. The load-bearing rules are the pack's own plus one: the zoom moves the LAYOUT (the scrollable spacer is the file's duration times the zoom, so panning is the pane's own `scrollLeft`) and the CANVAS IS VIEWPORT-ANCHORED (`position: sticky; left: 0`) because a canvas cannot be 300000 px wide - the layout is the file, the canvas is the window onto it, and it repaints on scroll; a zoom keeps the time under the pointer, restored on the next animation frame; the wheel listener is NATIVE and `{passive:false}` (React's own is passive, so a `preventDefault` inside it does nothing and the browser's Ctrl+wheel page zoom would fire on top), where Ctrl/Cmd+wheel zooms at the pointer, Shift+wheel gains and a BARE wheel scrolls sideways because time is this pane's axis. A drag on the waveform SELECTS (the ruler is the pan handle), a click seeks, and the status line reports the selection's duration, peak and RMS while NAMING where they came from (the samples, or the N-sample buckets); the DETAILS panel carries container, codec, rate, channels, bit depth, frames, duration, size, which decoder drew it, the pyramid's levels, and the file's metadata (RIFF LIST/INFO, BWF bext, AIFF NAME/AUTH/ANNO, FLAC Vorbis comments). PLAYBACK is WebAudio with the playhead driven by the AUDIO CLOCK (`currentTime - startedAt + from`), not a CSS animation, so the line cannot drift from the sound; a selection plays looped; a file too big to hold draws its waveform from a streaming pass and says why the transport is disabled. **Client-only on purpose**, like dsh-image and for the same reason: bytes come from the harness's own `workspaceFiles` remote (`readBytes` for a window, `readAll` for a whole file), which already resolves the path inside the conversation workspace, refuses a symlink out, requires a regular file and enforces its caps on the HOST side - so the package ships NO route, NO host state and NO path policy of its own, and `lib/index.js` is one no-op row whose only job is to put the browser bundle in the boot graph. **The window read is the design**: WAV/AIFF are decoded HERE, one 2 MiB `readBytes` window at a time (a deployment may configure the cap lower, and a refusal carries `details.limit`, so the window is halved and asked for again), the samples are folded into the PEAK PYRAMID and dropped, so a 2 GiB WAV draws at a bounded memory cost that a single `readAll` (32 MiB by default) would have forbidden - level 0 is one bucket per 256 samples of (min, max, rms) per channel and every level above groups exactly four buckets of the level below, so a decimated RMS is the root of the mean of its children's squares and the client picks the level from the pixels-per-second (zooming out changes WHICH level is read, never how many samples are walked). FLAC is decoded by the BROWSER (`decodeAudioData`), which is why its path reads the whole file and is capped by that single-read cap; its STREAMINFO is parsed HERE first, so a FLAC too big to decode still states its exact rate, channels, bit depth and length, and the decoder is given a context at the FILE's own rate so a 44.1 kHz file is not silently resampled (the panel says "resampled" when the browser refuses that rate). An unsupported codec is refused BY NAME (IMA ADPCM, MACE, GSM, ima4), a truncated file draws what exists and says the tail is UNKNOWN rather than silence, and MP3/M4A/Ogg are deliberately NOT claimed - the shipped preview's own `<audio>` element still plays them. The tab type is `extension`-band with the three families' suffixes and a `canOpen` that refuses anything else, so it REPLACES the shipped bare audio element by RANKING (extension 3 beats the shipped text type's fallback 1) and never by disabling a core row; there is deliberately NO guide entry. `exports.__internals` exposes the bundle's PURE half (the container parsers, the PCM decoder, the peak pyramid and the ruler math) so `check-client-bundles.mjs` can BUILD its own RIFF/WAVE, IFF FORM and FLAC byte by byte and assert the decoded numbers - the windowed-decode-equals-whole-file claim included - which is the only way a browser-only bundle's arithmetic gets verified at all. No fork, no core row disabled, no npm dependency, no vendored engine, nothing for `sync-vendored.ps1` to track
  - `packages/dsh-diagrams/` - **diagrams as a surface**: Mermaid and TikZ in ONE bundle (row `diagrams`). SIX tools - `diagram_write`, `diagram_patch`, `diagram_read`, `diagram_verify`, `diagram_publish`, `diagram_delete` - each taking an optional `scope` (`conversation` | `library`), whose every write is VALIDATED before it is stored: Mermaid by parsing the source headlessly with the SAME vendored engine the browser renders with (a CHILD process, `lib/mermaid-check.mjs`, installs a ~60-line DOM stub and loads `lib/vendor/mermaid.min.js` through `node:vm`, so the stub never touches the host process), TikZ by compiling it with the machine's own engine (`lib/latex.js`: `pdflatex` else `xelatex` else `lualatex`, argv only, `-no-shell-escape`, `MIKTEX_AUTOINSTALL=0`, `openin_any=p`/`openout_any=p`, a private temp cwd, a 20 s kill) - so a broken diagram returns the parser's/compiler's own line-accurate error (`diagram.tex:12: Package pgf Error: ...`) and the model fixes it in the same turn. Validation is followed by ADVISORY linting (alpha.3) that never changes the status: a picture with nodes and no edges, more nodes than a reader takes in at once, an unclosed-looking label, a Mermaid first line naming a different type than the engine parsed, a TikZ document that compiled to several pages or to no picture at all; two degenerate sources are refused in plain words rather than by the engine (empty/comments-only Mermaid, and a TikZ document with no drawing command, which pdflatex compiles to a blank page and reports as success). `diagram_verify { id }` re-runs the whole validation WITHOUT writing: it never bumps the revision and never discards the browser's render report. TWO skills (`skills/mermaid-diagrams/SKILL.md`, `skills/tikz-diagrams/SKILL.md`) registered at runtime from the package folder AND copied by both installers into `$DSH_HOME/skills`, where each copied folder carries a `.vn-harness-<package>` marker so a person's own skill is never overwritten and uninstall removes only what it wrote. STATE is ONE FILE per conversation (`$DSH_HOME/dsh-diagrams/sessions/<session>.json`, atomic temp+rename, 64 diagrams, 256 KiB per source, a 4 MiB SOURCE BUDGET per conversation - a typed `BUDGET` refusal checked on write AND patch, replacing a diagram charged once - and a 16 MiB file cap that nothing this plugin writes can reach, because a file past the cap reads as EMPTY and every diagram in the conversation would disappear at once) **plus a LIBRARY** (alpha.6): the SAME store class with a fixed file name instead of one per conversation, so `$DSH_HOME/dsh-diagrams/library.json` is ONE file for the whole harness and `diagram_write { scope: 'library' }` / `diagram_publish { id }` put a diagram in it. A bare id resolves LIBRARY-FIRST and then in the conversation, which is what lets `diagram_read { id: 'jepa-model' }` find a shared diagram from a chat that never saw it written; the address `dsh-resource://diagram/library/<id>` names NO conversation, so a citation survives the chat and the `diagram` tab type claims that address shape as well as the session one; the state route carries the library with every conversation's diagrams; and a panel edit writes back where the diagram ALREADY is, or editing a library diagram would quietly fork a conversation-only copy plus a content-addressed artifact cache (`artifacts/<sha256[0:24]>/{doc.tex,doc.pdf,doc.svg,doc.png,meta.json}`, LRU at 200 MiB). **Never a session event**: `dsh-session-persistence` refuses a log containing a type outside `KNOWN_SESSION_EVENT_TYPES` unless the envelope carries `ignorable: true`, and `Session.append()` cannot set that marker - a plugin-owned event type would make the conversation unreadable. **Never a projection**: a unit needs `zod` schemas and this pack ships ZERO npm dependencies (the profile installs live links, so a package dependency is not installed). The ROUTES are exact `connection.fetch` paths with **GET/HEAD/POST only** (the registry's own vocabulary), which is why the vendored engine is mermaid's own SINGLE-FILE browser build on ONE route (`/api/dsh-diagrams/vendor/mermaid.js`, ETag, ~3.4 MB, rebuilt by `vendor/build.mjs`, hash recorded in `lib/vendor/VERSION.json` and re-checked by the tracked route check) and why every write - including delete - is a POST. The BROWSER half registers two tab types: `diagram` (a resource kind, `dsh-resource://diagram/session/<session>/<id>` - one tab PER diagram, with the rendered picture, a source drawer whose Apply re-validates exactly like a model write, and an Export menu that SAVES EVERY FORMAT TO THE HOST'S DESKTOP (alpha.4: mmd/md/tex/pdf/svg/png, create-exclusively, the client naming a format and never a path, the Desktop resolved per request - never the conversation folder, with the browser download kept as the fallback) and a zoom ladder (25%-400%, remembered per diagram) with DRAG TO PAN over a picture laid out at 80% of the pane as its 100% rung - the ladder moves the layout BOX (never a CSS transform, which would scale into a clipped box with no scrollable area), a zoomed box STRETCHES its children (a column flex container sizes children to their CONTENT, so without that rule the box zoomed and the diagram did not - the bug that shipped first), panning is the canvas' own scrollLeft/scrollTop with the grab cursor MEASURED from real overflow, and a zoom keeps the point the reader was looking at) and `diagrams` (the index page `sidebar://diagrams`, whose guide entry at `order: 40` is what `+` / Start lists - after Files 10, Editor 20, History 30); plus a `tool.call.toolview` card per tool name that draws the diagram inline in the conversation with an "Open tab" link. Mermaid renders in the BROWSER from its own source (engine fetched once, evaluated as a classic script, cached per `(source, theme)`, themed off the app's scheme); TikZ renders from the HOST's compiled SVG (blob + `<img>`), and a failing compile that still produced a PDF is shown flagged as errored. **The Mermaid render path is the one place this package had a real interface bug** (alpha.3): `mermaid.render(id, source)` called with NO container element builds `#d<id>` on `document.body` and removes it again **only on the success path**, so every failed render left a div behind - and when the engine had drawn its own error diagram into it first, what stayed in the page was a full 2412x512 SVG reading "Syntax error in text / mermaid version 11.17.2", one per failure, until the tab was reloaded. The fix has four load-bearing parts and the tracked client check asserts each one: the source is **`parse()`d before `render()` is ever called**, the engine is initialized with **`suppressErrorRendering: true`** so it throws instead of drawing its error diagram, every render goes into **a container the plugin owns** (`mermaidHost()`, attached but laid out at zero size offscreen, because the engine measures what it draws), and a **`finally` sweeps** any `d<id>`/`i<id>` fixture anyway. A refusal comes back as a `MermaidError` carrying `phase: parse | render` and is drawn as TEXT - the parser's own lines, a Retry button and a route to the source drawer. **The state route carries each diagram's `source` AND `revision`** (alpha.3; it carried neither, so every tab and card drew from `undefined` and no render report could be matched to the revision it drew). **The browser reports what it drew** to `POST /api/dsh-diagrams/render-report`, stored per revision and read back by `diagram_read`/`diagram_verify` as `drawn` / `failed` / `stale` / `pending` - the one verdict the host cannot produce alone, since parsing proves the source is valid and only a renderer proves the picture exists. TeX is OPTIONAL: without an engine TikZ is stored and exported as `.tex`, and the index, the tab and the tool result all say so. No fork, no disabled core row, nothing for `sync-vendored.ps1` to track
  - `packages/dsh-pdf/` - **PDF as a surface the agent can actually read and SCAN** (row `pdf`). FIVE tools - `pdf_info` (pages, sizes, metadata, outline, attachments, forms/signatures, encryption, and per page whether there is a **text layer at all**), `pdf_read` (a page range in plain reading order or in a geometric `layout` reconstruction that groups runs by baseline and keeps columns and label/value pairs apart), `pdf_find` (literal or regex with page, line and context), `pdf_render` (page pictures through the host's own rasterizer, written as NEW PNGs) and `pdf_scan` (the SCANNER: recognize the pages that are a picture of text) - over a **vendored pdf.js 6.3.289**: the exact version and legacy build the harness's own preview inlines, so two renderers in one page can never disagree about a document. The engine lives in `lib/vendor/` (`pdf.min.mjs`, `pdf.worker.min.mjs`, 169 cMaps, 16 standard fonts, the `wasm/` JBIG2/OpenJPEG/qcms image decoders, pdf.js's Apache-2.0 LICENSE), is GENERATED by `vendor/build.mjs` (pinned in `vendor/package.json`, every file's bytes+sha256 and a digest per tree recorded in `lib/vendor/VERSION.json`, `build.mjs --check` a tracked check, and the tree's TEXT files pinned to LF in `.gitattributes` because those bytes are hashed and a Windows checkout would otherwise report phantom drift), and serves BOTH halves. Extraction runs in a **CHILD process** (`lib/extract.mjs`, argv only, 25 s deadline, `--max-old-space-size=512`, 8 MiB stdout cap), because a PDF is untrusted input handed to a large parser, and the child gates the parser itself: `isEvalSupported:false` (a document's embedded JavaScript is never evaluated), `useWorkerFetch:false` with no URL fetching anywhere, `enableXfa:false`, `useSystemFonts:false`, `disableFontFace:true`, cMaps/standard fonts/wasm as `file://` URLs. Identity is CONTENT: the SHA-256 of the bytes (streamed, memoized per `path+size+mtime`) names `$DSH_HOME/dsh-pdf/artifacts/<sha>/` (`index.json` document facts, `stats.json` per-page numbers merged as pages arrive, `pages/<n>.json` one page's text in both modes, atomic writes, LRU at 512 MiB), so an edited file can never serve a stale answer and `pdf_read` after `pdf_find` is free. The tab type is `pdf` at the **`extension` band with `patterns: ['*.pdf']`** and a `canOpen` that refuses anything but a `.pdf`: it REPLACES the shipped preview's bare PDF renderer **by RANKING** (`extension` 3 beats the shipped `text` type's `fallback` 1) - never by disabling a core row, which is why the shipped preview stays mounted as the fallback and every other file type keeps its surface. TWO address shapes: the ordinary `dsh-resource://file/session/<id>/<path>` and this package's own `dsh-resource://pdf/absolute/<whole-path-encoded>` for a document outside any workspace (a chat attachment under `$DSH_HOME/attachments/v1/files/...`, a file in Downloads), because the ordinary grammar drops the leading slash of a POSIX absolute path and would silently point elsewhere. ## Golden rules

1. Target the pinned dsh line only (`0.1.5-rc.1`, see `.dsh-version.json`).
   Test against what the owner runs. When DSH publishes a new line, bump the
   pin, run `scripts/sync-vendored.ps1` (the right bar, the Files tab and the
   open-in-app client are **forks** of that line's bundles), then adapt - do not
   silently chase master APIs.
2. Plugins stay **alpha** (`-alpha.N`) until the owner says "make it stable".
3. Never touch DeepSeek core packages, the harness profile internals beyond
   what `dsh plugin` does, or API keys. The pack owns its right bar by
   **forking** the core bundles into `packages/` and hard-disabling the core
   rows - never by editing an installed core file.
4. The browser bundle is read at harness boot. The web profile installs every
   bundle as a live link into this repo, so after editing a `client.js`
   the app only needs a RESTART of `npx @deepseek-ai/dsh web` plus a hard
   browser refresh (Ctrl+F5) - no reinstall. Reinstall (a plain
   `install.bat` / `./install.sh`, which re-adds on version change, or `-Force`)
   is only needed when the package set or version changes. There is no HMR
   unless a `pnpm run dev:web` watcher from the harness repo is running.
5. Client bundles are module-table files:
   `window.__ModuleLoader__.load({ id, factory })`. Browser-only: no Node
   imports; you may `require("react")`; the shell statically seeds `react`,
   `react/jsx-runtime`, `react-dom`, `react-dom/client`, `@deepseek-ai/cordis`,
   `@deepseek-ai/dsh-client-store`, `@deepseek-ai/dsh-client-ui-slots`,
   `@deepseek-ai/dsh-client-ui-primitives` and
   `@deepseek-ai/dsh-client-ui-dockkit`; anything else must be reached through
   `ctx.get(...)` after declaring it in the exported `inject` array
   (e.g. `["slots","sidebarRightTabs"]`). A client service is published with
   `ctx.reflect.provide(name, value)` (`sidebarRightTabs`, `sidebarRight`,
   `modals`); a service a consumer can live without - like `modals` - is
   resolved lazily at use time instead of being declared in `inject`. A tab type
   is TWO registrations: the static definition through
   `ctx.sidebarRightTabs.register(...)` and the keyed body/title through
   `ctx.slots.inject("sidebar.right.pane.tab"...)` with `key` = the
   definition's `id`; the "+" control lists every type that declares a `guide`
   entry on its definition.
6. Installer scripts are ASCII-only (smart quotes/dashes have broken parsing
   before). The `.ps1` half runs on **Windows PowerShell 5.1 and 7**; the `.sh`
   half is **POSIX sh** (dash/bash on macOS/Linux) and must never call
   PowerShell. Keep the two halves in step: same flags (`-Force`, `-Plugin`,
   `-DshHome`, `-ProfileName`, `-DshVersion`, `-Target web|cli`), same messages,
   same behaviour. After editing a `.ps1`, parse-check it; after editing a `.sh`,
   run `sh -n` (see below).
7. When the pack branding is mentioned, the repo name is `vn-harness`.
   Commits are authored as `vecnode <vecnode@users.noreply.github.com>`
   (git config is set in the repo).

## Commands

```bat
:: Windows
install.bat                   :: installs into the web profile (the only target)
install.bat -Force            :: re-add bundles even when versions match
run.bat                       :: start the app + open it in Chrome (foreground; Ctrl+C stops it)
run-desktop.bat               :: start the app in a NATIVE WINDOW instead (builds app/ first)
uninstall.bat
```

```sh
# macOS / Linux - Node.js with npm/npx; no PowerShell needed
./install.sh                  # the web profile (the only target)
./install.sh -Force           # re-add bundles even when versions match
./run.sh                      # start the app + open it in Chrome (foreground; Ctrl+C stops it)
./uninstall.sh
```

`install.bat` drives the PowerShell half and `install.sh` the POSIX half; the
run launcher is the root `run.bat` / `./run.sh` pair (`run.bat` drives
`scripts/run-web.ps1`). Each can also be run
directly:
`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-all.ps1 -Force`
(Windows, and `-File scripts/run-web.ps1` for the app) and
`sh scripts/install-all.sh -Force` (macOS/Linux).

`-Target cli` is accepted as an alias for the web profile; there is no desktop
target any more, and `run-desktop.bat` is not one - it is a launcher for the web
profile (see `app/`), which installs nothing. Everything runs through
`npx --yes @deepseek-ai/dsh@<pinned>`; pnpm is bootstrapped locally under
`tools/pnpm<major>` (the profile's pnpm major is read from
`node_modules/.modules.yaml`).

> Package retirements: the panel was `dsh-focus` (row `focus`) until alpha.10,
> when it became `dsh-files` (row `files`), and in alpha.2 of the editor the
> whole first-generation Files package was dropped when the harness grew its own
> right Sidebar with a Files tab. From then on the pack **forks** the bar
> (`dsh-rightbar`, `dsh-rightbar-files`) and disables the core rows instead of
> depending on them. Both install scripts keep the
> `$legacyNames = @('dsh-focus','dsh-files')` prune so an upgraded profile drops
> the old bundles. Add future removed/renamed packages to that list in both
> scripts.

## Iterating on a change (quick loop)

```powershell
# 1. syntax-check a JS/PS/SH file
node --check packages/dsh-editor/lib/client.js
node --check packages/dsh-rightbar/lib/index.js    # forked client.js is generated
sh -n scripts/install-all.sh scripts/uninstall-all.sh install.sh uninstall.sh run.sh
$t=$null;$e=$null; [System.Management.Automation.Language.Parser]::ParseFile(
  'scripts/install-all.ps1',[ref]$t,[ref]$e); $e.Count   # expect 0
$t=$null;$e=$null; [System.Management.Automation.Language.Parser]::ParseFile(
  'scripts/run-web.ps1',[ref]$t,[ref]$e); $e.Count       # expect 0
cmd /c "run.bat -Help"                                  # entry point: usage, exit 0
cmd /c "run.bat -BadFlag < nul"                         # ...and a bad flag exits 1
cargo test --manifest-path app/src-tauri/Cargo.toml     # the desktop shell's
                                                        # launch-token rules
cmd /c "run-desktop.bat -Help"                          # desktop entry point, exit 0

# 2. after a harness-line bump, move the forks forward (then review the diff).
#    sync-vendored.ps1 is maintainer tooling and is the one script that wants
#    pwsh on macOS/Linux (`powershell -NoProfile -ExecutionPolicy Bypass -File`
#    on Windows).
pwsh -NoProfile -File scripts/sync-vendored.ps1
pwsh -NoProfile -File scripts/sync-vendored.ps1 -Check

# 3. push the bundles into the web profile
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-all.ps1 -Force   # Windows
sh scripts/install-all.sh -Force                                                     # macOS / Linux

# 4. verify the served bundle really contains the change (optional smoke):
$env:DSH_HOME = "$HOME/.dsh"          # Windows: "$env:USERPROFILE\.dsh"
npx --yes @deepseek-ai/dsh@0.1.5-rc.1 web --no-open --port 3099   # background
# then GET http://127.0.0.1:3099/?token=<token-from-log>, and confirm the boot
# HTML lists dsh-rightbar / dsh-rightbar-files / dsh-editor / dsh-gittree /
# dsh-terminal / dsh-modal /
# dsh-themes / dsh-open-in-app / dsh-diagrams / dsh-pdf / dsh-image / dsh-audio
# client.js and does NOT LOAD the disabled core rows
# (@deepseek-ai/dsh-client-ui-sidebar-right|files, @deepseek-ai/dsh-client-ui-open-in-app) -
# note that those names still appear in OTHER bundles' `inject` arrays, so match
# the /plugins/??<name>/client.js URLs, not the bare strings.
# It must also NOT list dsh-vn-master: the master is blank, with no client half.
# POST /api/dsh-open-in-app/open {"app":"explorer","path":"<abs dir>"} must open
# a real file-browser window; PUT /api/dsh-editor/file {"create":true,...} must
# create the file (and answer 409 EXISTS on a second try).

# 5. commit as vecnode and push
git add -A; git commit -m "describe the change"; git push
```
